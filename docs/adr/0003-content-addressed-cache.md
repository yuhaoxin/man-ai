# 0003 缓存键：块级内容寻址

- 状态：接受
- 日期：2026-11-12
- 决策来源：[#7](https://github.com/yuhaoxin/man-ai/issues/7)、[#5](https://github.com/yuhaoxin/man-ai/issues/5)、[#8](https://github.com/yuhaoxin/man-ai/issues/8)、[#9](https://github.com/yuhaoxin/man-ai/issues/9)

## 背景

同一段 man 文本会在不同页面、不同调用之间重复出现；同一页面在不同机器、不同安装路径下也可能完全相同。缓存要同时满足：

- 页面更新、模型或端点切换、提示词改版时失效。
- 页面路径、mtime、工具版本不导致无谓失效。
- 多个进程并发读写不损坏数据。
- 不保存原文，降低隐私面。

候选方案：

1. 页面绝对路径 + mtime/size 作为键：实现直观，但 man 页更新只改 mtime 时会误失效，跨页面无法复用，路径不同也无法命中。
2. 整页内容哈希：能跨路径复用，但页面里改一行就整页失效，块级翻译的粒度被浪费。
3. SQLite 或嵌入式 KV：查询方便，但引入数据库文件、迁移与并发写复杂度。
4. 块级内容寻址 + 目录树单文件：键只由输入与影响输出的版本字段构成，文件即译文。

## 决策

采用方案 4。

- 键 = BLAKE3-128(`CACHE_VERSION | PROMPT_VERSION | 形态 | 规范语言标签 | 规范化端点 URL | 模型名 | 思考强度 | 输入字节`)，每段前置 8 字节小端长度，输出 32 位小写十六进制。
- 不含页面路径、section、mtime/size、工具版本、并发度、终端宽度、`max_tokens`、页首行与尾行。
- `CACHE_VERSION` 覆盖回写协议、校验语义与键结构；`PROMPT_VERSION` 覆盖提示词模板与固定请求参数（`temperature`、`stream`）；思考强度是用户配置且影响输出，作为独立键字段。
- 存储为 `$XDG_CACHE_HOME/man-ai/v1/<键前 2 位>/<完整键>`，文件内容就是译文原始字节；目录 0700，文件 0600；`tempfile` 写临时文件后 `rename` 原子替换，不 `fsync`。
- 无 TTL；`cache_max_mb` 默认 200，进入翻译路径前按 mtime 剪枝到上限的 80%；失败与回退不入缓存；`-k` 整批一个条目；命中不更新 mtime。
- 只存译文，键不可反推内容；`cache_enabled=false` 时不读不写不建目录。

## 后果

- 同一段文本在不同页面、不同安装路径、不同机器之间天然共享缓存。
- 任何影响成功译文内容的改动都必须显式递增版本号或进入键字段，否则旧条目会继续命中；`max_tokens` 因不影响成功条目的内容而被排除。
- 剪枝按最后写入时间而非最后使用时间，长期只读的高频条目可能被淘汰。
- 端点 URL 的非规范等价写法会产生重复条目；查询串与片段被禁止，避免请求路径拼接歧义。
- 缓存目录可以整体拷贝，但 v1 不提供同步、预热或来源校验。
- 并发 miss 时多个进程重复请求同一块，后写覆盖；不做单飞合并。
